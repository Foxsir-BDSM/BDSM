> 重构后源码全部位于 `src/`，站点 URL 与磁盘路径解耦（例如 `src/launcher/index.html` 对外是 `/index.html`）。

## 二、三种启动方式

### 方式 A：Vite 开发服务器（推荐日常开发，:5173）

```bash
npm run dev
```

浏览器打开 **http://localhost:5173/**（注意用 `localhost`，Vite 默认绑定 IPv6 `::1`）

**特点**
- 支持热更新（改源码即时生效）
- `@` 别名、`import.meta.env` 等构建期特性全部可用
- 内置 dev 路由中间件，把站点 URL 映射到 `src/` 下的真实文件

### 方式 B：零依赖静态服务器 · 源码模式（:5600，最接近真实发布）

```bash
npm run serve
```

浏览器打开 **http://127.0.0.1:5600/**

**特点**
- 不经过 Vite 转换，直接以静态文件提供 `src/`
- 无热更新，但路径行为与生产环境最接近
- 不依赖 Vite，出问题时可用它交叉验证

### 方式 C：构建产物模式（:5601，验证上线形态）

```bash
npm run build          # 构建并整理出部署结构
npm run serve:dist     # 提供 dist/
```

浏览器打开 **http://127.0.0.1:5601/**

## 三、⚠️ 必须知道的预期行为（不是 Bug）

未登录访问受保护页面时，`guard.js` 会**主动重定向到 `/landing.html`**。手工测试时看到"跳回首页"属正常。

| 页面 | 未登录访问的结果 |
|:---|:---|
| `/index.html`（控制中心） | 重定向 → `/landing.html` |
| `/admin.html`（管理面板） | 先 alert「需要管理员权限」，再跳首页 |
| `/admin-article.html`（内容管理） | 重定向 → `/landing.html` |
| `/modules/*`（各模块） | 可正常打开（模块页未接入 guard，靠数据层降级） |
| `/landing.html`、`/about.html`、`/auth.html` | 公开，正常打开 |

**要完整验证受保护功能，需要先登录。** 用 `auth.html` 注册一个账号即可（默认角色 `self`）。
若要测试管理后台，需要在 Supabase 后台把该账号的 `raw_user_meta_data.role` 改为 `admin` 或 `subadmin`。

## 七、常见问题排查

| 现象 | 原因 | 处理 |
|:---|:---|:---|
| `npm run dev` 后所有页面 404 | dev 路由中间件未生效 | 确认 `vite.config.js` 里 `plugins: [devRoutePlugin()]` 存在，并**重启** dev server |
| 浏览器打不开 `127.0.0.1:5173` | Vite 只绑了 IPv6 | 用 `http://localhost:5173/`，或 `npm run dev -- --host 127.0.0.1` |
| 页面跳回首页 | guard 正常拦截未登录 | 先登录，见第三节 |
| 页面弹出「需要管理员权限」 | 当前账号非管理员 | 在 Supabase 后台改 `role` |
| 端口被占用 | 上一次的服务器没关 | `npm run serve -- --port 5610` 换端口，或结束占用进程 |
| dev server 崩溃报 `EBUSY ... watch` | 有程序在项目内写入临时文件被 Vite 监听 | Chrome 调试配置目录请放在项目外（`tools/runtime-check.mjs` 已用系统临时目录） |
| 知识区/任务区显示「暂无文章」 | 无 GitHub Token | 预期降级；配置 `VITE_GITHUB_TOKEN` 或访问 `/admin-article.html` 手动填 Token |
| 档案馆列表一直转圈 | Fillout API 不可达 | 检查网络；控制台执行 `clearArchiveCache()` 重试 |
