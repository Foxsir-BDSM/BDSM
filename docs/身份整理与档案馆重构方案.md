# 身份整理 + 档案馆重构方案
## 第一阶段：身份模型与默认过滤设计

**日期**：2026-10-03
**前置决策**（你已确认）：
1. 身份由 12 种精简为 **4 种**（男S / 女S / 男M / 女M），上下位整合为一个板块
2. 新增**性取向**维度（男 / 女）
3. 档案馆按「用户身份 + 性取向」做**默认过滤**
4. 档案馆内的「认证」仅表示**档案为本人知情填写**，与平台角色 `verified` 是两件事
5. 账号 ↔ 档案关联本轮不做

# 一、身份模型重构

## 1.1 从 12 到 4

| 现在（12） | 重构后（4） |
|:---|:---|
| 男S / 女S / 男Dom / 女Dom / 男Z / 女Z | **男S / 女S** |
| 男M / 女M / 男Sub / 女Sub / 男B / 女B | **男M / 女M** |

**合并映射**（用于兼容已注册用户的旧元数据）：

| 旧 identity | 新 identity |
|:---|:---|
| `male_S` / `male_Dom` / `male_Z` | `male_S` |
| `female_S` / `female_Dom` / `female_Z` | `female_S` |
| `male_M` / `male_Sub` / `male_B` | `male_M` |
| `female_M` / `female_Sub` / `female_B` | `female_M` |

> 旧用户不需要重新注册：读取时做一次映射即可。
> 原来的 S / Dom / Z 细分不丢——保留为一个**可选的自称标签**（见 1.3）。

## 1.2 新增维度：性取向

| id | 标签 |
|:---|:---|
| `hetero` | 异性 |
| `homo` | 同性 |
| `bi` | 双性 |
| `unsure` | 未定 |

## 1.3 身份的完整信息结构

```
身份   男S / 女S / 男M / 女M          ← 必选，决定等级路径与档案默认视图
取向   异性 / 同性 / 双性 / 未定        ← 必选，决定档案默认视图
自称   可选补充标签（如 Dom / Z / Sub / B）  ← 保留原 12 分类的细分表达
```

**这样处理的好处**：分类维度从「6 种互斥身份」变成「4 种身份 × 4 种取向 + 自由自称」，
表达力没有下降，但结构清晰、可组合、可用于过滤。

# 二、档案馆重构

## 2.1 从两个档案馆到一个统一档案库

| 现状 | 重构后 |
|:---|:---|
| `sub-archive` 下位者档案馆（45 字段，完整） | **统一档案库** |
| `dom-archive` 上位者档案馆（**全空，打开即白屏**） | 合并为同一套机制，用身份区分 |

统一的档案库按身份分区：男S 区 / 女S 区 / 男M 区 / 女M 区。
当前实际只有 M 侧有数据配置，S 侧字段表需另建（见 2.4）。

## 2.2 默认过滤逻辑（核心）

**前提**：档案记录自带 `身份`（男S/女S/男M/女M）与 `取向` 两个字段。

默认视图 = **互补位置的同取向档案**

| 访问者 | 档案侧 | 默认看到 |
|:---|:---|:---|
| 男S + 异性 | M 侧 | **女M + 异性** |
| 男S + 同性 | M 侧 | **男M + 同性** |
| 女S + 异性 | M 侧 | **男M + 异性** |
| 男M + 异性 | S 侧 | **女S + 异性** |
| 女M + 同性 | S 侧 | **女S + 同性** |

**访问者身份决定去哪个分区，取向决定默认筛出哪一批。**

**兜底与可覆盖**（重要，否则新用户会看到空白）：

| 情况 | 处理 |
|:---|:---|
| 记录缺少身份或取向字段 | 归入「未标注」，默认视图**不排除**，但排序靠后 |
| 访问者取向为「未定」 | 不按取向过滤，只按身份分区 |
| 访问者未设身份 | 显示全部（回到当前行为） |
| 用户主动切换 | 顶部筛选条永远可改（身份分区 / 取向 / 全部），默认只是**初始值** |

> 设计原则：**默认是便利，不是限制。** 用户随时能看全部。

## 2.3 「认证」字段的语义修正

| 项 | 现状 | 重构后 |
|:---|:---|:---|
| 档案馆字段 `fwK2mQMoxto` | 标签「认证」，含义模糊 | 改为「**本人填写**」——表示该档案由本人知情填写 |
| 平台角色 `verified` | 认证用户 | **不变**，仍表示账号权限层级 |

两者不再混用：档案上的标记说明**这份档案的真实性来源**，
账号角色说明**这个用户能看到多少**。

> ⚠️ 字段 ID 不变（`fwK2mQMoxto`），只改标签与说明文案，
> 因此不需要动 Fillout 表单结构。

### 2.4.3 隐私与权限

保留现有机制，但修两处既有缺陷：

| 缺陷 | 修法 |
|:---|:---|
| `PRIVACY_RULES` 与 `PRIVACY_DEPENDENCIES` 双份手工同步 | 由 `PRIVACY_RULES` **自动派生** `PRIVACY_DEPENDENCIES` |
| 列表宽严判定不一致（列表宽松 / 详情严格） | 统一用 `isPrivacyApproved()` 宽松判定 |

权限层级重构（修「admin 无优势」与「self 就能看私密影像」）：

| 角色 | 可见范围 |
|:---|:---|
| guest（未登录） | 仅卡片级信息：姓名 / 年龄 / 地区 / 身高体重 / 星级 |
| self（普通用户） | + 基本档案字段（职业学历、情感状态、关系意向） |
| verified（认证用户） | + **联系方式**、**生活照** |
| subadmin（次级管理） | + **私密影像**、**详细性经验字段** |
| admin（根源管理） | 全部（含管理用字段） |

> 关键变化：**私密影像从 self 提到 subadmin**，认证成为真实门槛。

## 5.2 占位字段怎么换成真的

`src/shared/config/archive/instances.js` → `FILTER_FIELDS`：

```js
FILTER_FIELDS: {
  identity:    { filloutId: null, label: '身份', options: ['男S','女S','男M','女M'], placeholder: true },
  orientation: { filloutId: null, label: '取向', options: ['异性','同性','双性','未定'],  placeholder: true },
}
```

**表单补齐后只需两步**：
1. 把 `filloutId: null` 换成真实字段 ID
2. 把这两个 ID 登记进 `HOME_ONLY_FIELD_IDS`（若仅首页用）

筛选逻辑、UI、权限都不用改，位置筛选会自动从「不可用」变为「生效」。

## 5.3 三层降级设计（核心）

档案缺字段时不能直接失效，因此做了三层：

| 层级 | 条件 | 行为 |
|:---:|:---|:---|
| 1 | 表单有身份/取向字段 | 精确筛选 |
| 2 | 无字段，但记录归某馆 | 按馆别判定身份（当前女馆 → 女M / 下位者） |
| 3 | 都判定不出 | 归「未标注」，**默认不排除** |

## 5.4 实施中发现并修复的两个体验缺陷

### 缺陷 1：位置筛选造成空白页

**现象**：女M + 异性 → 推导出「位置 = 上位者」；而女馆记录经降级判定全为「下位者」
→ 一条都匹配不上 → **空列表**。

**修法**：位置筛选**只在档案带真实身份数据时生效**（`hasRealIdentityData()`）。
单馆状态下位置维度标注为「暂不可用」，并提示表单补齐后自动生效。

### 缺陷 2：性别筛选造成空白页

**现象**：女M + 异性 → 找男性；女馆全是女性 → 仍为空。

**修法**：加入**空集兜底** —— 默认筛选若会清空列表，自动放宽为「只按身份」，
让用户先看到内容，再由筛选条自行收窄。

> 原则：**默认筛选绝不能把列表清空。** 默认是便利，不是限制。
