# 邮箱自动填写 —— 实现步骤

**目标**：用户已登录时点「去填写档案」，邮箱自动带进表单，用户看不到也改不了。

**原理**：站点把邮箱拼进 URL → 表单用「隐藏字段」接收 → 提交时随答案一起落库。

依据：[Fillout · URL Parameters/Hidden fields](https://www.fillout.com/help/url-parameters)、
[Use URL parameters in form embeds](https://www.fillout.com/help/embedded-url-parameters)、
[Using Logged-in Data](https://www.fillout.com/help/logged-in-data)。

---

# 一、你要在 Fillout 里做的（4 步）

## 第 1 步：加一个隐藏字段

在表单**最前面**（身份题之前）加一个字段：

| 项 | 值 |
|:---|:---|
| 字段类型 | **Hidden fields**（在左侧字段面板搜 "Hidden"） |
| Label | `用户邮箱` |
| **URL parameter 名称** | `user_email` ← **必须与站点拼的参数名完全一致** |

> 如果左侧面板里找不到 Hidden fields，也可以用一个 **Short answer** 字段代替，
> 稍后在属性面板把它隐藏（见第 3 步）。

## 第 2 步：同样方式再加两个（可选但推荐）

用于人工核对，万一邮箱绑定失败时能派上用场：

| Label | URL parameter 名称 | 用途 |
|:---|:---|:---|
| 用户昵称 | `user_nickname` | 后台核对 |
| 用户ID前缀 | `uid` | 后台核对（UUID 前 8 位） |

## 第 3 步：确认它在填写页不可见

隐藏字段默认不显示给填答者。若是用 Short answer 代替的，需要在属性面板：

- 打开 **Logic** 或字段设置，把该字段设为 **Always hidden**（始终隐藏）
- 或者：**Required 关闭** + 在 **Logic** 里设 `Show if` 一个永不成立的条件

**关键：不要让它出现在填答者眼前。**

## 第 4 步（可选）：把它映射到可见字段

如果你希望填答者**看到**自己的邮箱并能修改，就多加一步：

在「联系方式」字段（`Q-B11`）的 **Prefill** 设置里，映射来源选
`用户邮箱` 隐藏字段。这样邮箱会预填到可见输入框，用户可以确认或改。

> **两种模式二选一**：
> - **静默模式**（推荐）：仅隐藏字段接收，用户全程无感
> - **可见模式**：同时预填到可见框，用户能看到并自行修改
>
> 静默模式更符合你"不需要用户额外操作"的要求。

# 二、我要在站点里改的（1 处）

## 现状

`src/modules/sub-archive/js/home.js:434`

```js
window.open(CONFIG.FORM_URL, '_blank');
```

裸开表单，不带任何参数。

## 改成

```js
import { getCurrentUser } from '@/shared/js/auth.js';   // ← 文件顶部加导入

// 构造带用户参数的 URL
async function buildFormUrl() {
  const base = CONFIG.FORM_URL;
  const user = await getCurrentUser();
  if (!user?.email) return base;                 // 未登录 → 原样打开（走后台补录兜底）

  const p = new URLSearchParams({
    user_email: user.email,
    user_nickname: user.user_metadata?.nickname || '',
    uid: (user.id || '').slice(0, 8),
  });
  return `${base}?${p.toString()}`;
}

// 打开时改为：
window.open(await buildFormUrl(), '_blank');
```

**注意**：`window.open` 必须由用户点击直接触发，否则会被浏览器拦截弹窗。
所以要先 `await` 再 `open` 可能被拦。稳妥写法是**先用占位窗口**：

```js
async function openForm() {
  const w = window.open('', '_blank');   // 先同步开一个空窗口（不被拦）
  w.document.write('<p style="font-family:sans-serif;padding:40px">正在准备表单…</p>');
  w.location.href = await buildFormUrl();  // 再跳转
}
```

## 参数含义

| 参数 | 来源 | 用途 |
|:---|:---|:---|
| `user_email` | `user.email` | ★ **绑定主键** |
| `user_nickname` | `user_metadata.nickname` | 后台核对 |
| `uid` | `user.id.slice(0,8)` | 后台核对（不传完整 UUID，减少暴露） |

**为什么只传 UUID 前 8 位**：完整 UUID 没有核对价值（人也读不出来），
传前 8 位足以在后台唯一识别，同时少暴露一点信息。

# 三、怎么验证成功

## 3.1 直接测 URL

在浏览器里手工打开（把邮箱换成你的测试账号）：

```
https://forms.fillout.com/t/sZm1g43KzHus?user_email=test@example.com&user_nickname=测试&uid=a1b2c3d4
```

- 表单应该正常打开
- **页面上看不到"test@example.com"** ← 隐藏字段生效
- 提交后，在 Fillout 的 **Results** 里应能看到 `user_email` 列有值

## 3.2 测试清单

| # | 测试 | 期望 |
|:---:|:---|:---|
| 1 | 未登录点入口 | 表单正常打开，`user_email` 为空（走兜底） |
| 2 | 登录后点入口 | 表单打开，`user_email` = 登录邮箱 |
| 3 | 检查填写页 | **看不到邮箱字段** |
| 4 | 提交后查 Results | `user_email` 列有正确值 |
| 5 | 手工改 URL 里的邮箱 | 能改成别的值 ← **这是已知风险，见第四节** |
| 6 | 重复提交 | 应做幂等更新而非新建（需先配 Pre-fetch） |

# 四、已知风险与两种加固

## 风险

有人手工构造 URL：

```
...?user_email=别人的邮箱
```

就能把提交写到别人名下。

**危害评估**：

| 场景 | 影响 |
|:---|:---|
| 恶意冒充他人 | 污染他人档案 ← **真实风险** |
| 自己填错邮箱 | 只影响自己 |

## 加固方案 A：只允许本站嵌入（低成本）

把表单改成 **iframe 嵌入**到你的站点，而不是 `window.open` 新窗口。

- 好处：外部直接访问的表单页可以关掉公开入口
- 局限：iframe 的 URL 参数仍可被改，**不解决冒充**

## 加固方案 B：签名令牌（真正解决）

站点生成 `email + HMAC 签名`，一起传给表单；
后台收到后**验签**，签名不对就丢弃或转入待绑定队列。

```
user_email=test@example.com&sig=<hmac_sha256(email+日期, 私钥)>
```

**需要一个后端来验签** —— 这正是 `answer.me-x.workers.dev` 可能的用武之地。

**我的建议**：
- **现在**：先上静默模式 + 加固 A。你的邮箱是登录后才有的，正常用户不会去改 URL
- **将来**：档案一旦涉及真实身份与影像（现在已经涉及），补上签名令牌

# 五、和「档案馆合并」一起做，省一次返工

你最近决定：档案表单加「身份」「取向」两个字段用于筛选
（`FILTER_FIELDS` 现在还是占位，`filloutId: null`）。

**建议这两个字段和 `user_email` 隐藏字段一次加完**：

| 字段 | 类型 | 参数名 | 作用 |
|:---|:---|:---|:---|
| 用户邮箱 | Hidden | `user_email` | ★ 绑定账号 |
| 身份 | Dropdown | — | 档案筛选（你已在计划中） |
| 取向 | Dropdown | — | 档案筛选（你已在计划中） |

加完之后：
1. 站点改 1 处代码（上面第二节）
2. `FILTER_FIELDS` 的 `filloutId` 换成真实字段 ID
3. **绑定与筛选同时生效**

# 六、附：如果 Fillout 的 Hidden fields 不好用

备选：**用 Subform 或 "Logged-in Data" 功能**

Fillout 有 [Using Logged-in Data in Your Form](https://www.fillout.com/help/logged-in-data)，
如果你的表单开启了登录（Login page 字段类型），可以直接拿到填答者的登录信息。

**但这条路对你的场景不合适**：那要求填答者在 **Fillout 侧**登录，
而你的人是在 **Supabase 侧**登录的 —— 两套账号体系不通。

所以 **URL 参数仍是你的最优解**。

---

# 七、一句话总结

**Fillout 加一个 `URL parameter = user_email` 的隐藏字段；
站点在跳转时把登录邮箱拼进 URL。**

用户在登录状态下点一下，邮箱就跟着进去了 —— 他看不到，也不用填。
