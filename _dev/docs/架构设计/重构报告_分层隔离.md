## 二、隔离原则

### 2.1 三条清晰的边界

| 层 | 职责 | 依赖方向 |
|:---|:---|:---|
| **launcher** | 访客可见的公开门面 + 控制中心 | → shared |
| **admin** | 管理员专属操作台 | → shared, modules（读取档案 API） |
| **modules** | 业务功能，自包含（HTML + JS + CSS + 自有图片） | → shared |
| **shared** | 跨层复用的基础设施 | 不依赖任何上层（无循环） |

**依赖是单向的**：`launcher / admin / modules` → `shared`。`shared` 内部零反向依赖。

### 2.2 模块的"自包含"含义

每个模块文件夹内含**它自己的**：
- 页面（HTML）
- 逻辑（js/）
- 样式（css/）
- 模块自有静态资源（如 `sub-archive/OIP-C.jpg`）

模块之间**不互相引用**，只通过 `shared` 通信。新增模块 = 新建一个 `src/modules/<name>/` 文件夹，无需改动其他模块。

### 2.3 导入约定（重要）

| 场景 | 写法 | 原因 |
|:---|:---|:---|
| JS 模块互引 | `@/shared/js/auth.js` | `@` 别名指向 `src/`，Vite 构建期解析，路径与文件位置解耦 |
| HTML/CSS 的静态资源 | 相对路径 `../../shared/css/main.css` | 这些引用**不经过 Vite 打包转换**，必须是真实相对路径才能在静态服务器下工作 |
| JS 中的站点路由字符串 | **根绝对** `/index.html`、`/modules/sub-archive/` | JS 会被打包进 `/assets/*`，相对路径会失效 |

> 这条边界是本次重构最容易踩坑的地方：JS 与 HTML 的路径语义相反。

### 2.4 站点路径映射

| 磁盘路径 | 站点 URL |
|:---|:---|
| `src/launcher/index.html` | `/index.html` |
| `src/launcher/about.html` | `/about.html` |
| `src/admin/admin.html` | `/admin.html` |
| `src/modules/sub-archive/detail.html` | `/modules/sub-archive/detail.html` |
| `src/shared/js/auth.js` | `/shared/js/auth.js`（源码直读时） |
| `src/shared/assets/images/*` | `/shared/assets/images/*` |
| 打包产物 | `/assets/*` |

`npm run build` 会自动把 `dist/src/launcher/*` 与 `dist/src/admin/*` 上移到 `dist/` 根，产出与上表一致的**真实部署结构**。

### 校验器的工作原理

`tools/ref-check.mjs` 按**浏览器真实请求路径**规则解析每一条引用：

1. `/xxx` → 站点根（经 `ROUTE_RULES` 映射到 `src/launcher`、`src/admin`、`src/modules`、`src/shared`）
2. `./` `../` → 相对当前文件所在目录
3. `@/xxx` → `src/`（与 `vite.config.js` 的 alias 保持一致）
4. `http(s)://` / `data:` / `#` → 跳过
5. 目录式 URL → 追加 `index.html`

因此它**同时**验证了源码结构与部署路由两件事，任何路径改动都会被立即捕获。
